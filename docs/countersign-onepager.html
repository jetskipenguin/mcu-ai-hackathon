Countersign

AI where it's allowed. Humans where it's required. Proof of which was which.

A student takes a distance-education course from a personal laptop. Their browser has an AI assistant — built in, like Perplexity Comet, or added as an extension. They ask it to “finish this,” and it does: it completes the quiz, writes the discussion post, and reads the personnel record on screen — sending that data to a commercial model in someone else's cloud. The learning system saw a logged-in student doing normal things. It has no way to know an agent did the work, or that sensitive data just left. Countersign is a governance layer any web application can adopt to close that gap.

The problem, and the fix

Without Countersign

The agent carries the student's logged-in session — the right cookies, the right credentials. To the application, its clicks are indistinguishable from a human's. It submits the exam, ghost-writes the graded post, and scrapes the record. No exam proctor is watching a browser; no vendor guardrail pauses on a quiz.

With Countersign

At the moment an action matters, the app demands a countersign: a fingerprint, security key, or CAC touch that cryptographically proves a human is physically present, bound to that exact action. The agent can use the session. It cannot press the sensor. It stalls — and every action is logged with proof of who did it.

Three ways to govern — the app decides, per action

Require the human
Exam submission, payment approval
A hardware presence proof is required to complete the action. No proof, no submit. This is the guarantee an agent cannot forge.
Make the record honest
Discussion posts, written work
AI use isn't blocked — it's disclosed. The author attests, keystroke telemetry is recorded, and contradictions surface to faculty. Governance, not surveillance.
Protect the data
PII, PHI, CUI on the page
Sensitive fields carry machine-readable CUI markings and are masked from suspected-agent sessions until a human verifies presence.

How it works

  • Presence, not detection. Built on WebAuthn / FIDO2 — the same standard behind the CAC. The proof is a signature over the specific action, not a guess about whether a bot is present.
  • Two ways to deploy. A script and a policy file for apps you own, or a reverse proxy in front of a legacy system — no code changes.
  • Provenance you can audit. Every governed action is logged with the actor, the rule, and the presence proof.

Where AI helps build it

An LLM reads an application's pages and drafts the governance policy — identifying exam submissions, sensitive fields, and where disclosure is needed — choosing only from the 126 official CUI Registry categories, with a citation for each rule. A human approves before anything takes effect. It runs in GovCloud, so the model that reads your pages is authorized for what it sees. That's how a legacy system gets governed without hand-writing rules.
